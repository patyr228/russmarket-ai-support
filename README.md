# Автоматизация утренней сводки support-отдела («Руссмаркет»)

## 2. Введение
Гибридное решение для автоматической сверки статусов CRM и рабочих чатов.  
Система формирует приоритезированную утреннюю сводку для support-отдела, чтобы сотрудники быстрее замечали кейсы, требующие вмешательства.  
Решение работает полностью локально (Ollama) с учётом требований 152-ФЗ.

---

## 3. Способ обработки
Предлагается гибридный подход:
1. **Rule-based подготовка данных**: Скрипт собирает статусы из CRM и историю сообщений из рабочих чатов, отсекает системный шум и выполняет базовые проверки дедлайнов.
2. **Локальная LLM + Structured Outputs**: Модель анализирует неструктурированные переписки, сопоставляет их с официальными статусами CRM и возвращает результат строго по схеме Pydantic.
3. **Безопасность**: Вся обработка персональных данных происходит локально, без передачи во внешние облачные API.

## 4. Сводка по четырём кейсам (понедельник, 10:00)

### С-17 - Оформление сотрудника
* **В CRM:** первый выход завтра, документы ожидаются.
* **Из чата:** сотрудник отправил фото документов руководителю в личку.
* **Нужно вмешательство:** да (документы не дошли до системы).
* **С чего начать:** запросить у руководителя пересылку документов в CRM.

### С-24 - Увольнение сотрудника
* **В CRM:** последний рабочий день сегодня, подтверждение руководителя отсутствует.
* **Из чата:** сотрудник говорит, что с руководителем всё обсудили.
* **Нужно вмешательство:** да (нет официального подтверждения).
* **С чего начать:** запросить у руководителя письменное подтверждение закрытия смены.

### П-08 - Поставка карт
* **В CRM:** доставка запланирована до 10:00, статус «В пути».
* **Из чата:** курьер сообщил о задержке до 13:00.
* **Нужно вмешательство:** да (дедлайн уже просрочен).
* **С чего начать:** оповестить точку о новом времени прибытия и зафиксировать отклонение.

### П-09 - Поставка карт
* **В CRM:** статус «Принято», приёмка подтверждена в 09:20.
* **Из чата:** получатель подтвердил получение и проверку количества.
* **Нужно вмешательство:** нет.
* **Действия:** не требуются.

## 5. Описание первого запуска
Решение забирает данные по API из CRM и историю сообщений из рабочих чатов.  
Сводка формируется по расписанию утром и отправляется в закрытый канал или дашборд support-отдела.  
Сотрудник перед началом работы смотрит сводку, в первую очередь обращая внимание на кейсы с высоким приоритетом. Перед действием рекомендуется быстро сверить вывод с оригинальной перепиской.  
На старте запускаем систему в тестовом режиме параллельно с ручной работой в течение одной недели и совместно с руководителем support-отдела замеряем время обработки инцидентов «до» и «после».
