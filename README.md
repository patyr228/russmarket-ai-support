# Автоматизация утренней сводки support-отдела («Руссмаркет»)

Тестовое задание на позицию «Специалист по AI-автоматизации».

## 🛠 01. Способ обработки (Архитектура решения)

Предлагается **гибридный подход**, обеспечивающий безопасность (152-ФЗ) и высокую точность:

1. **Rule-based подготовка (Обычные правила):** 
   Скрипт собирает статусы из CRM (через API) и историю сообщений из чатов (API мессенджеров). На этом этапе отсекается системный шум (технические сообщения ботов) и проверяются базовые дедлайны (например, если время доставки уже прошло).
2. **Локальная LLM + Structured Outputs:** 
   Модель (в коде используется `qwen2.5:7b` через Ollama) анализирует неструктурированные переписки, сопоставляет их с официальными статусами CRM и возвращает строго типизированный JSON благодаря библиотеке `Pydantic`.
3. **Безопасность:** 
   Вся обработка персональных данных происходит локально, без передачи во внешние облачные API (OpenAI, Anthropic и т.д.).
4. **Надежность:** 
   В коде реализованы механизмы ретраев (`tenacity`) на случай сбоев локальной модели и профессиональное логирование (`logging`).

## 🚀 03. Описание первого запуска

На старте решение забирает данные по API из CRM и историю сообщений из рабочих чатов. Скрипт запускается по расписанию (через `cron` или `n8n`), обрабатывает данные и отправляет готовую сводку в закрытый Telegram-канал или дашборд support-отдела. 

Сотрудник утром открывает сводку и в первую очередь смотрит на кейсы с меткой `HIGH`. Перед действием он может кликнуть на ID кейса, чтобы быстро сверить вывод ИИ с оригинальной перепиской. 

Для валидации эффективности мы запустим систему в тестовом режиме (параллельно с ручной работой) на одну неделю. Вместе с руководителем отдела мы замерим время обработки инцидентов «до» и «после», а также соберем обратную связь, чтобы убедиться, что ИИ не пропускает критичные случаи.

## 🧪 04. Что проверено, а что предстоит проверить

**✅ Проверено на практике (в рамках тестового):**
* Логика сопоставления CRM-статусов и переписок.
* Работа Structured Outputs (Pydantic) и стабильность парсинга.
* Архитектура локального контура (Ollama) и обработка ошибок (ретраи).

**⏳ Нужно проверить при внедрении:**
* Реальные эндпоинты и лимиты API CRM «Руссмаркет».
* Форматы доступа к рабочим чатам (Telegram, WhatsApp API).
* Реакция сотрудников support-отдела на формат выдачи данных.
